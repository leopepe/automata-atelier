## Context

See [proposal.md](./proposal.md) and [capability spec](./specs/grafo-search-workspace/spec.md). `Graph::dijkstra_cost` in `grafo/src/graph.rs` currently initializes an `f64::INFINITY` vector and new heap per nontrivial query; `Graph::shortest_path_filtered_cost` resolves labels, tests both endpoints, then searches. `dijkstra_path` is separate. The read-only sibling investigation measured warm epoch gains for narrow synthetic queries, but cold and changing-endpoint controls were not consistently faster. The target checkout's `grafo/docs/testing.md` exists and supplies test conventions. Design discussion: [#60](https://github.com/leopepe/automata-atelier/issues/60); ADR 0006 is **proposed**, not accepted.

## Goals / Non-Goals

**Goals:** Explicit opt-in reuse for cost-only search; equivalence with existing cost-only results and errors; safe reuse through early exit, filter panic, graph switches and generation wrap; retain independent concurrent readers without mutating `Graph`.

**Non-Goals:** Shared/TLS cache, planner integration, full-path workspace, automatic thresholds, sparse/touched maps, alternate heap, weight-constructor policy changes or guaranteed speedup.

## Decisions

1. **Public seam:** Re-export `SearchWorkspace` from `grafo/src/lib.rs`; `SearchWorkspace::new()` and `Default` construct empty reusable state. Add `Graph::shortest_path_cost_with_workspace(from, to, &mut workspace)` and `Graph::shortest_path_filtered_cost_with_workspace(from, to, filter, &mut workspace)` with the existing `Fn(&NodeAttrs) -> bool` bound, label/error and endpoint-check order. Keep existing cost methods and `dijkstra_cost` unchanged, not wrappers around freshly allocated workspace. The new filtered method owns a private workspace Dijkstra helper in the same `graph.rs` seam; no separate writer for type and query logic. A small amount of parallel cost-loop code is preferable to changing the default hot path solely for reuse. Alternative: replace default with workspace; rejected by cold/mixed measurements.
2. **State and query lifecycle:** Private `Vec<f64>` distances, `Vec<u32>` stamps, `u32` generation and `BinaryHeap<(Reverse<u64>, u32)>`; no stored graph identity, pointers or shared mutable fields. Before each query's predicate invocation or search-state read, resize both arrays to the selected graph's node count (new entries have stamp zero), clear the heap while retaining capacity, advance the generation; on rollover, fill stamps with zero then start generation at one. Initialize a node's distance when its stamp differs, including source at zero. A fresh epoch invalidates every prior distance regardless of graph size or same-sized ID reassignment; this does not prevent memory retained at a previous large heap capacity. Perform preparation before endpoint checks so a filter panic at either endpoint cannot leave the next query depending on old state. When the label lookup errors, no predicate is invoked; the next successful query still prepares independently. Filter invocation order follows the existing `||` short circuit. Offer no explicit reset or size management public method: a caller drops the workspace to release retained capacity; normal queries resize metadata exactly to graph size and retain allocated capacity. Alternative: graph-keyed workspace or exposed reset/resize; rejected because complete per-query invalidation already handles graph changes without pointer identity assumptions.
3. **Numeric and heap parity:** Reuse existing `Reverse(new_cost.to_bits())` ordering and strict `<` relaxation, stale-entry check, `0.0` source cost, and `f64::INFINITY` for unseen nodes via stamp tests. With overflow to infinity, `new_cost < INFINITY` remains false. Constructor currently uses `debug_assert!(w.is_finite() && w >= 0.0)` rather than a typed validation error; keep this policy, not a new rejection variant. Compare costs to existing API on zero/-zero, fractional and finite extremes; avoid claiming equivalence for unsupported invalid weights in release. Alternative: zero-sentinel encoding; rejected for added representation complexity and unproven broad performance.
4. **Proof and measurement:** Before production edits, capture baseline tests and FULL repo benchmark surface for both core crates sequentially (`cargo bench -p grafo-dag --bench performance` then `cargo bench -p goap-planner --bench performance` with saved before baselines). Add focused RED external tests/compilation evidence and internal rollover test, then implement GREEN. Extend grafo benchmark deterministically for fixed reachable subgraph with isolated padding; warm and cold setup, amortized batches, chains/layered/dense, broad/unreachable/mixed endpoints, filtered, full-path control, graph switches and independent concurrent workspaces. Run FULL after benchmarks for both crates sequentially and sample native profiles for corresponding workloads. CI benchmark subset still runs unchanged. Include correctness checks within bench setup if measurements compare equivalent graph queries; timings alone do not establish equivalence. A concurrent test with separate workspaces tests ownership/results, not all thread interleavings.

## Risks / Trade-offs

- [Cold setup and broad-search overhead] → Publish cold/warm and per-shape before/after numbers; keep default as control; no universal speed claim.
- [Generation wrap and stale heap entries] → Force rollover by internal unit setup, exercise stale/early exit across alternating queries; clearing heap before each search handles retained entries but does not validate corrupted source graph data.
- [Filter panic, graph switch with identical numeric IDs] → Prepare before predicates, test `catch_unwind(AssertUnwindSafe(...))` then next query, resize/same-size reassignment; unwinding safety does not promise recovery from abort or double panic.
- [Memory retention] → Document O(V) distances/stamps plus heap peak capacity per workspace, graph-size resizes and release on drop; retaining capacity does not cap memory usage.
- [Profiling policy exception] → `cargo flamegraph --version` exited 101 in the operator packet. Do not install, elevate permissions or weaken CI. Label native macOS `sample` SVGs as cycle-local diagnostic substitutes paired with each full before/after bench log, document collection/idle worker limitations and explicitly mark standard flamegraph gate unmet. Do not name a native SVG `flamegraph-*` as if it satisfied the standard tool.

## Migration Plan

Opt-in API is additive. Existing callers need no migration. Review/ratify ADR separately; proposed status is not approval. Rollback removes only new APIs, tests, bench cases and docs; existing algorithms remain intact. Publish performance trade-offs in dated comparison plus canonical `grafo/docs/performance.md`, with README links inspected for needed updates. Do not change CI, profiling policy or planner production code.
